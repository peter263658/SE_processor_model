## 1. Architecture Summary (dim=256)

### 1.1 Encoder / Decoder

- 6-stage encoder + 6-stage decoder, both Complex Depthwise-Separable Conv2d (5×1 kernel, stride (2,1) on freq axis).
- Channel ladder (`kernel_num`, real-valued = 2× complex channels):
  `[2] → 16 → 32 → 64 → 128 → 256 → 256`
- Decoder uses transposed conv with skip connections (concat along channel dim).
- BatchNorm = `NaiveComplexBatchNorm2d` (independent re/im affine, **8 params per channel**).
- Activation = `ComplexPReLU` (single scalar slope per layer).

### 1.2 Attention block (`MultiAttnBlock`)

```
input (complex 256-dim)
  ↓ input_proj          : Linear(256→256, complex)        ← see §3.2
  ↓ ComplexMultiheadAttention
      ├── MHA_re : in_proj_weight [768, 256] real (Q/K/V fused), out_proj.weight [256, 256] real
      └── MHA_im : in_proj_weight [768, 256] real (Q/K/V fused), out_proj.weight [256, 256] real
  ↓ element-wise combine: z_re = RR − II,  z_im = IR + RI
  ↓ output_proj         : Linear(256→256, complex)        ← see §3.1, §3.2
```

`flatten_size = (kernel_num[-1]/2) × (fft_len / 2^len(kernel_num)) × 2 (binaural) = 128 × 1 × 2 = 256` happens to equal `embed_dim = 256`. This is **load-bearing** for §3.2.

### 1.3 ComplexMHA executes 4 real-MHA passes per forward

- `_forward_real`  : `MHA_re(x.real)` and `MHA_im(x.imag)`
- `_forward_imag`  : `MHA_re(x.imag)` and `MHA_im(x.real)`

Each real MHA pass = `in_proj` (Q/K/V) + `softmax(QK^T)` + `score @ V` + `out_proj`. **4 softmaxes per inference step.** Per ASIC spec, softmax is non-pipelined → this 4× softmax serialization is a real bottleneck.

### 1.4 Parameter counts

| Module | Params | fp8 size |
|---|---:|---:|
| Encoder (all stages)   | ~93 K   | ~91 KB  |
| Decoder (all stages)   | 113,078 | 110.4 KB |
| └─ Decoder stage 0 (256→128) | 67,586 | 66.0 KB |
| └─ Decoder stage 1 (256→64)  | 33,794 | 33.0 KB |
| └─ Decoder stage 2 (128→32)  |  8,706 |  8.5 KB |
| └─ Decoder stages 3–5        |  ~3 K  |   ~3 KB |
| MHA block (input_proj + ComplexMHA + output_proj) | 657,920 | 642.5 KB |
| └─ input_proj (complex)              |  65,792 | 64.3 KB |
| └─ MHA_re/im in_proj_weight (each)   | 197,376 | 192.8 KB |

> Each 256×256 real matrix = **64 KB fp8 / 32 KB W4** (= exactly one WBUF). All projection matrices in MHA (in_proj, out_proj, input_proj, output_proj) are 256×256-class, so single-WBUF-load tiling becomes possible at W4.

## 3. Recommended Architecture-Level Optimizations

Ordered by impact-to-implementation-cost ratio. Each item lists what the HW team gains, and what the algorithm side must commit to (retrain / no retrain).

### 3.1 Fuse `output_proj` with `MHA_re/im.out_proj` — pipeline-only win

**What:** Pre-multiply offline:
```
F1 = output_proj.W_re @ MHA_re.out_proj
F2 = output_proj.W_re @ MHA_im.out_proj
F3 = output_proj.W_im @ MHA_re.out_proj
F4 = output_proj.W_im @ MHA_im.out_proj
```
Apply F1..F4 directly to the four pre-`out_proj` attention pooling outputs (A1..A4); combine element-wise.

**HW gains:**
- **Pipeline depth halved** in the post-attention path: 2 sequential matmul stages → 1 stage. (`out_proj` and `output_proj` no longer have a serial dependency.)
- **Activation buffer pressure reduced**: the four intermediates `M1..M4` (each `[T, 256]`) no longer need to be held between stages.

**HW gains NOT achieved by this fusion:**
- ❌ Same total FLOPs (8 matmuls of 256×256 either way — confirmed by recount).
- ❌ Same total weight storage (4 matrices of 256×256 either way).

**Algorithm side cost:** None. Pure offline weight pre-computation, no retrain.

### 3.2 Remove `input_proj` and `output_proj` outright — large compute & storage win

**Why this is possible:** With current config `flatten_size = embed_dim = 256`, both `input_proj` and `output_proj` are complex Linear 256→256 with **no dimension change** and **no nonlinearity** between them and their neighbors. Their cascade with the surrounding linear layers (`in_proj_QKV` and `out_proj`) is mathematically equivalent to a single linear, i.e. they are **redundant** and contribute nothing to the model's function class.

```
[input 256] → input_proj(256→256) → in_proj_QKV(256→768)   ≡   [input 256] → in_proj_QKV(256→768)
attn_out → out_proj(256→256) → output_proj(256→256)         ≡   attn_out → out_proj(256→256)
```

**HW gains (per inference step):**
| | Saved |
|---|---|
| `input_proj`  compute  | 4 × [256×256] real matmuls = ~262 K ops |
| `output_proj` compute  | 4 × [256×256] real matmuls = ~262 K ops |
| **Total compute saved**       | **~524 K ops / step (~33% of MHA-block compute)** |
| Weight storage saved   | 2 × 65,792 params ≈ **128 KB fp8 / 64 KB W4** |
| Pipeline stages saved  | 2 (one before MHA, one after) |
| DMA loads saved        | 2 weight tiles per inference |

**Algorithm side cost:** Retrain (or fine-tune from existing checkpoint with the two modules zeroed and removed). No accuracy floor expected since the model class is unchanged.

> ⚠️ This saving **only applies while `flatten_size == embed_dim`**. If the algorithm side later changes `kernel_num`, `fft_len`, or makes `embed_dim ≠ flatten_size`, the projections become non-redundant.

**Do NOT instead try to *fuse* `input_proj` into `in_proj_QKV`.** Because `input_proj` output feeds two consumers (MHA_re and MHA_im) with different weights, fusion duplicates the work into both consumer paths and increases compute by ~50% and storage by ~50%. Removal is the correct move; fusion is a trap.

### 3.3 NOVELTY — Weight-tied ComplexMHA (`MHA_re ≡ MHA_im`)

**Claim:** If we constrain `MHA_re` and `MHA_im` to share weights (call the shared module `M`), the 4-pass complex attention collapses to:
```
ComplexMHA(x) = (1+i) · [M(x.real) + i·M(x.imag)]
```
i.e., **2 real-MHA passes + one complex-scalar multiply** instead of 4 real-MHA passes.

**HW gains:**
- **MHA compute reduced 50%**: 4 passes → 2 passes through Q/K/V proj, attention, score×V, out_proj.
- **MHA weight storage reduced 50%**: only one set of `(in_proj, out_proj)` instead of two.
- **Softmax serialization reduced 50%**: 4 softmaxes → 2 softmaxes per inference step. Direct latency win since softmax is non-pipelinable per the ASIC spec.
- **DMA volume on MHA weights halved.**

**Algorithm side cost:** Retrain from scratch (or warm-start with averaged weights `M = (MHA_re + MHA_im)/2`). Function class is restricted (the off-diagonal real/imag mixing is now coupled), so empirical validation on MBSTOI / ILD / IPD is required.

**Why this is publishable:** Standard "naive" complex MHA from DCCRN-family literature uses the 4-pass formulation by default. Showing that a tied-weight variant retains binaural quality while halving MHA cost is a clean architectural contribution.

### 3.4 Tied-scale ComplexBN (4 params instead of 8) — enables BN folding

**Background:** Standard `NaiveComplexBatchNorm2d` (8 params per channel: `γ_re, β_re, μ_re, σ_re²` and `γ_im, β_im, μ_im, σ_im²`) **cannot** be folded into the preceding complex conv. The reason: folding requires the same affine scale on both real and imaginary outputs of the conv, but NaiveComplexBN allows `a_re = γ_re/√(σ_re²+ε) ≠ a_im = γ_im/√(σ_im²+ε)`. If `a_re ≠ a_im`, the folded operator no longer fits the complex-linear form — it would require 4 independent real weight matrices (2× storage of a complex conv).

**Fix:** Constrain BN to a **tied-scale** variant — one complex scale + one complex bias per channel (4 effective params, with `a_re = a_im`). With this tying, BN folds cleanly:
```
W'   = a · W       (complex scale absorbed into complex conv weight)
b'_re = a · b_re + β_re − a·μ_re
b'_im = a · b_im + β_im − a·μ_im
```
At inference the BN module disappears; the conv produces the post-BN output directly.

**HW gains:**
- One pipeline stage removed per encoder/decoder block.
- BN element-wise mul-add unit not needed at inference.
- BN running stats (`μ, σ`) not stored on chip.

**Algorithm side cost:** Retrain with the constrained BN class. Restrictiveness is small (real and imag share one global scale per channel), and tied-scale ComplexBN is reported in the literature with negligible accuracy impact.

### 3.5 Attention mask as ROM, not on-chip arithmetic

For fixed `T` (per audio chunk) and fixed `window_size = 31`, the causal sliding-window mask is a constant. The construction code in [model.py:255-263](DCNN/models/model.py#L255-L263) is unnecessary at inference. Either:
- Hard-code the mask pattern in HW, or
- Store a one-bit-per-entry bitmap (157 × 157 bits ≈ 3 KB, negligible).

**HW gains:** No on-chip `triu` / `arange` / element compare. Trivial saving but removes an inference-time arithmetic dependency.

**Algorithm side cost:** None.

## 5. Recommended Implementation Order

| Order | Item | Retrain? | HW change | Impact |
|---|---|---|---|---|
| 1 | §3.5 Attention mask as ROM | No | Trivial RTL | Small / free |
| 2 | §3.1 Fuse `output_proj` ↔ `MHA.out_proj` | No (offline weight pre-mult) | Modify post-attention dataflow | Pipeline win, no FLOP saving |
| 3 | §3.2 Remove `input_proj` / `output_proj` | Yes (single retrain) | Drop two stages from MHA wrapper | ~33% MHA-block compute, ~128 KB fp8 weight |
| 4 | §3.4 Tied-scale ComplexBN + fold | Yes | Drop BN modules in conv path | ~12 BN stages eliminated |
| 5 | §3.3 **Novelty — Weight-tied ComplexMHA** | Yes (single retrain, possibly with §3.2 in same run) | Drop one of MHA_re / MHA_im, scale output by `(1+i)` | **50% MHA compute & weight, 50% softmax serial** |

Items 3, 4, 5 can share a single retraining run.
