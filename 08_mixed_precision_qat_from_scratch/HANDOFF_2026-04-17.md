# 交接：W4A8 QAT 重訓與 config 清理（2026-04-17）

## 背景

前一輪 W4A8 QAT fine-tune 跑 60 epochs，最佳 checkpoint 落在 epoch 50（顯示還在改善就被停了），整體成效不理想。這輪調整訓練超參 + 修 training pipeline 的 bug + 清 config。

## 本輪修改摘要

### 1. 訓練超參調整（`config/config.yaml`）

| Key | 舊值 | 新值 | 理由 |
|---|---|---|---|
| `learning_rate` | 0.0001 | **0.0005** | W4 QAT 在 1e-4 下太保守 |
| `learning_rate_decay_steps` | [3, 8] | **[15, 30, 45]** | 配合新的 120 epoch budget |
| `n_epochs` | 60 | **120** | 先前 best = epoch 50/60，還在降 |
| `early_stopping.min_delta` | 0.01 | **0.001** | 原本太粗，會誤停 |
| `early_stopping.patience_in_epochs` | 3 | **8** | 容忍 plateau |
| `train_checkpoint_path` | 註解掉 | **uncomment** | **重要** — 前一輪可能根本沒載 pre-trained checkpoint，這可能才是結果差的主因 |

Checkpoint 路徑（確認存在）：
`/raid/R12K41024/07_mixed_precision_qat/epoch=134-step=130680.ckpt`

### 2. 🔥 Bug 修復：EarlyStopping 從未生效

**檔案**：[DCNN/utils/base_trainer.py](DCNN/utils/base_trainer.py)

**問題**：`EarlyStopping` 物件有被建立並 append 進 `callbacks` list，但傳給 `pl.Trainer.__init__` 的 `callbacks=` 是**硬寫死**的 `[progress_bar, checkpoint_callback]`，上面那個 list 完全沒用到。所以不管 config 寫什麼，早停都不會觸發。

**修法**：
- 實際把 `callbacks` list 傳進 `trainer_kwargs`
- 尊重 `early_stopping.enabled` flag
- 補 `mode="min"` 和 `verbose=True`（log 可看 wait counter）

**驗證方式**：跑起來後 log 應該出現：
```
Metric validation_loss improved. New best score: ...
Monitored metric validation_loss did not improve in the last N records. Best score: ...
```

### 3. Masking mode 改為 'C'（rectangular complex multiply）

**檔案**：`config/config.yaml`，`masking_mode: 'E'` → `'C'`

理由：E (`|x||s|·exp(j·(∠x+∠s))`) 和 C (4 實乘 + 2 加) **數學完全等價**，但 C 是硬體自然形式（一顆複數 MAC，無 CORDIC）。訓練結果功能不變，FUSIONS.md 之後可直接寫 "complex multiply" 省掉等價性證明。

**R 被排除**：`(r·mr, i·mi)` 會破壞 phase coupling，ILD/IPD 幾乎一定掉。

### 4. Config 審計 — 清掉 dead keys

經全 codebase grep，以下 key 設了但**從未被讀取**，已從 `config.yaml` 移除：

| 移除的 key | 原因 |
|---|---|
| `model.use_clstm` | 只存 `self.use_clstm` 後不再用；attention path 已取代 RNN |
| `model.use_cbn` | 整個 codebase 沒有 grep 到；`NaiveComplexBatchNorm2d` 是 hardcoded |
| `model.bidirectional` | 被 `**kwargs` 吃掉後沒傳給任何元件 |
| `training.strategy` | [trainer.py:29](DCNN/trainer.py#L29) 已註解掉 |
| `training.logger` | 沒有任何地方讀；TensorBoard logger 無條件建立 |

**`model.win_type: 'hann'` → `'hamming'`**：`Stft/IStft` 實際 hardcode `hamming_window`（[feature_extractors.py:22,44](DCNN/feature_extractors.py#L22)），使用者確認就是要 hamming，所以改 config 對齊現實。

> ⚠️ **和 FUSIONS.md 不一致**：`08_software_to_hardware/FUSIONS.md` 有寫 "Hann, length=128" 要存進 ROM。若照 FUSIONS 產 `stft_window.fp16.bin`，會跟訓練用的 hamming window 不同，硬體推論結果會錯。**下次硬體 handoff 前要更新 FUSIONS.md 或重產 window ROM**。

### 5. `model.yaml` / `training.yaml` 清空

這兩個檔被 `defaults:` 載入，但內容（如 `win_len:400`, `fft_len:512`, `embed_dim:512`, `num_heads:32`）是舊架構的 stale value，靠 `config.yaml` 在 Hydra override 時覆蓋。為避免誤會，兩個檔改成只留空 map：
```yaml
# training.yaml (and model.yaml similarly)
training: {}
```
單一事實來源 = `config.yaml`。
