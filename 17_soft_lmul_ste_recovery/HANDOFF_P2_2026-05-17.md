## 1. P2 設計（再次確認，給 reviewer cross-check）

### 1.1 P2 在 g42 上加什麼

```
P1 g42 (已 sign-off):
  decoder layer i:
    x        →  pointwise_x    (gx=4, in=128, out=128)  ┐
                                                         ├─ add  →  depthwise_T
    skip     →  pointwise_skip (gs=2, in=128, out=128)  ┘

P2 g42 + skip_select_ratio=r:
  decoder layer i:
    x                         →  pointwise_x    (gx=4, in=128, out=128) ┐
                                                                         ├─ add → ...
    skip → index_select(K)   →  pointwise_skip (gs=2, in=K,   out=128) ┘
                K = round(group_size * r) * groups_skip
```

`K` 是 group-aware keep count：每個 skip group 各保留 `round(group_size * r)` 個 channel，總和 `keep_per_group * groups`。這保證 P1 grouped pointwise 的 warm-start 在 P2 surgery 後**仍能對齊到正確 group structure**。Flat top-K（不分 group）會破壞這個對齊，被 spec §5.1 / Codex `_validate_skip_indices` 兩處擋下。

### 1.2 P2 sweep matrix

| Variant | mode | ratio | 目的 |
|---|---|---|---|
| `s075_first` | first_n | 0.75 | sanity（不分 score，每 group 取前 K 個） |
| `s075_topk` | topk_l1 | 0.75 | 主推（valset 跑 encoder，per-group L1 排序取 top K） |
| `s050_first` | first_n | 0.50 | sanity（aggressive） |
| `s050_topk` | topk_l1 | 0.50 | 主推（aggressive） |

`learned_gate` 與 ratio < 0.5 不在本 sweep（per spec §5.1）。

## 2. Code review findings（Claude 對 Codex P2 的觀察）

### 2.A 已修：`P1_CKPT` hardcode

原 [make_phase2_skip_warmstarts.sh:23](scripts/make_phase2_skip_warmstarts.sh#L23) 把 `outputs/p1_grouped/g42_2026-05-17_04-01-16/.../epoch=27-step=27104.ckpt` 釘死。若有人重跑 g42 finetune，新 timestamp 出來時 script 會 break。

改成 auto-detect：撈 `outputs/p1_grouped/${P1_VARIANT}_*` 最新 dir，再從 `checkpoints/` 撈最新 non-last ckpt。若失敗印錯誤訊息並提示用 `P1_CKPT=...` 覆寫。Sanity check 過——auto-detect 撈到的檔跟原 hardcode 同一個。

### 2.B Design strengths（不用改，僅作 reviewer cross-check 參考）

1. **`_skip_keep_count` 強制 group-aware**（model.py:196-210）：`keep = keep_per_group × groups`。對 P1 g42 warm-start 是必要條件。
2. **`_validate_skip_indices` 四重檢查**（model.py:238-267）：count / range / unique / **group-wise ordering**（每段 chunk 必須落在自己 group 的 channel range）。第 4 個是 hard 保證。
3. **Parametrized weight handling**（convert script :52-60）：W4A8 QAT 用 `register_parametrization`，真正 weight 存在 `*.parametrizations.weight.original`。Codex 先 try parametrized 才 fallback `weight`——漏掉這條 P2 ckpt 會 load 失敗。
4. **Buffer key 跨 train/eval 一致**：model.py register `decoder.skip_indices_{stage}`，convert script 寫進同名 key 到 state_dict。Lightning prefix `model.` 自動偵測（convert :149-154）。
5. **L+R encoder 都跑** for L1 stats（precompute :168）：skip subset 是兩耳共享的，L1 估也兩邊都算。
6. **Indices sort by channel index (not by score)** 在 `topk_groupwise_indices`：產出 deterministic、canonical，比較 / debug 容易。
7. **Fail-fast guards**：`topk_l1` 沒 `skip_indices_path` raise；`skip_select_ratio < 1.0` 配 `mode=off` raise；`channel_shuffle=True` raise NotImplementedError（per spec §7 deferred）。
8. **`_DecoderBlockSplit` 用 numeric key `"0"`/`"1"`/`"2"`**（model.py :270-294）：跟 legacy `nn.Sequential` 同 key 序，state_dict 可跨格式 load（P1 warmstart 是 split-class 但 BN/PReLU key 名跟 Sequential 一樣）。

### 2.C 要 reviewer 注意（不 blocker，但執行前知道）

**C1. Last decoder layer (idx=1)**：out=1（mask head），`gcd(in_skip=8, out=1)=1` 強制 groups_skip_eff=1。在 s050 下會剩 4/8 skip channels。**這層在 g42 已經 fallback 到 dense（沒被 group）**，P2 把它再砍 50% 是新增動作。可能對 IPD 有 marginal 影響（spec §9 risk row：「P1 `groups=4` ILD 退化 → 鎖 g≤2 或只在 deepest 層 group」同精神，但 P2 是反向：last 層保不保 skip channel）。
- 真有問題：可以加 per-layer override `last_layer_skip_select_ratio=1.0` 跳過 last 層。**現在不加，等 sweep 結果出來判斷**。
- 風險低因為 last 層 dec_pw MAC 占整體 0.5%，cut 也省不到多少。

**C2. precompute_skip_indices 用 `batch_size=8` 跑 valset**：跟 P1 訓練的 `batch_size=32` 不同，但對 L1 sum 沒影響（accumulator across batches）。Codex 應該是顧及記憶體選 8，OK。

**C3. `make_phase2_skip_warmstarts.sh` 對 index file 有 `[ -f ]` reuse check**：意思是 smoke artifact `p2_skip_indices_g42_first_n_r075.pt` 會被 reuse。但 first_n 是 deterministic（純按 group_size × ratio 算），smoke 版 = fresh 版，**正確性無風險**。topk_l1 沒 smoke artifact，全會 fresh-gen。

**C4. `subset_grouped_weight` 對 `old_groups>1` 的 reshape pattern** (convert :140-146)：
```python
blocks = weight.reshape(old_groups, out_per_group, full_in_per_group, kh, kw)
```
PyTorch grouped Conv2d weight shape 是 `[out, in/groups, kH, kW]`，內部是 `[group_0_out_chunk, group_1_out_chunk, ...]` interleaved by output。Codex 的 reshape 假設 weight 沿 dim 0 是「out_per_group × groups」連續排列（先 group_0 所有 out_per_group 個 channel、再 group_1）—— **這是 PyTorch 的標準 layout，正確**。第 1 dim `full_in_per_group` 也是「該 group 內部能看到的 input channel」，這也對。
- Cross-verify：spec §3.2 講 grouped warm-start 用 block-diagonal init，這跟 convert 假設的 layout 一致；P1 g11 R0 verifier 已隱含驗過。

## 3. 預期 sweep 結果 + gate 標準

### 3.1 標準

`g42` baseline 在 P1 sign-off：
- 20-pair MBSTOI Enh: 0.8091
- Full 750-pair MBSTOI Enh: 0.8361 (= baseline 0.8360)
- ILD 3.263 dB, IPD 16.04°

P2 gate（與 P1 同精神）：
- 20-pair sanity：|Δ MBSTOI vs g42| ≤ 0.005 = within noise
- Full 750-pair：MBSTOI ≥ 0.831（baseline -0.005）+ ILD/IPD 退化 ≤ 5%

### 3.2 個別變體預期

| variant | MAC 收益 vs g42 | 期望 quality |
|---|---|---|
| s075_first | -16.6% dec_pw | sanity baseline，可能略差 topk |
| s075_topk | -16.6% dec_pw | 主推 best case；應該 |Δ| < 0.003 |
| s050_first | -33.2% dec_pw | sanity baseline，可能開始掉 |
| s050_topk | -33.2% dec_pw | 主推 aggressive；可能 |Δ| < 0.01，需 full eval 才能判 |

### 3.3 失敗 fallback path

如果結果像這樣：
- 全部 s050 都掉 > 0.005 → 鎖在 s075，P2 best = s075_topk
- s075_topk vs s075_first 沒有顯著差別 → topk_l1 沒帶來 quality 提升，但 inference behavior 兩者等效（都 deterministic），無 RTL 差別 → 採 topk_l1（與 spec 一致）
- s075 也掉 > 0.005 → P2 整體不接受，**回到 g42 當 final RTL candidate**
